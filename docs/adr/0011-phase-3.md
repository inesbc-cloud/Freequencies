# 0011. Phase 3: working together, papers in order, numbers people can read, skins

- Status: proposed
- Date: 2026-11-25

## Context

Phase 3 (prompt: `docs/prompts/phase-3.md`) adds what promoters need beyond planning one event:
understanding their numbers, sharing with other collectives, keeping legal papers in order in a
heavily policed nightlife, and a playful choice of looks — all in English and Portuguese.

## Decision

**Navigation.** Home · Calendar · Production · Promo · Network · Resources · Reports, with EN | PT
top right, HELP and the skin switcher bottom right. Venues moved into Network, Funding into
Resources, Analytics became Reports. Co-promotion lives inside Budget (one line until used), not as
its own module, to keep Production short.

**Data, all Scala ext items (no new core module):**

| Kind | Where | What |
|---|---|---|
| `deal` | event, newest wins | a deal scenario (flat / door split / guarantee + % / guarantee vs %) |
| `copro` | event, newest wins | partners with shares, who paid / holds what, settled flag |
| `artist` flags | event | optional `local`, `wnb`, `first` on a booking — only ever counted |
| `poll`, `vote` | event or Network anchor | quick polls; each person's newest vote counts |
| `venue`, `gear`, `borrow`, `reply`, `crew` | Network anchor | shared directory, gear library with requests, crew pool (people add themselves) |
| `lesson` | Network anchor | a debrief row a collective chose to share |
| `inspection` | event | after-the-fact inspection log: who, what they checked, outcome, note — no names |
| `inspect-pattern` | Network anchor | opt-in anonymised copy: month, area, body, checks, outcome |

The **Network anchor** is one event in the Lisboa community calendar with field `fq_network =
"anchor"` (oldest wins), hidden from every view, like the Funding library's anchor.

**Reports** answer three questions with a visible owner: how did this event go (also a Results card
in the event panel), how is this collective doing this year (with funder numbers and "copy for an
application"), what's on in Lisbon (weekends and crowded nights from Lisboa + public listings).

**Legal toolkit** is information, not advice: content in `fq/lib/legal-content.js`, bilingual,
PT first, each item with sources and a "last checked" date; a "draft, under legal review" badge
stays until `REVIEWED = true` after a lawyer or legal clinic has reviewed it. No live "police are
coming" alerts and no names of officers or attendees anywhere.

**Skins** swap the design tokens in `fq/Fq.qml` live (colours, display face, border weight,
backdrop): Classic and a kooky 8-bit universe (stars, UFOs abducting a cow, a waving alien, a
ringed planet, a rocket; pixel sprites in `fq/PixelSprite.qml`). A 90s rave skin was tried and dropped. Promo images keep their own look. The pixel
face (Press Start 2P, OFL) loads from `qml/fonts/` if present; system fonts stand in.

## Consequences

- Android needs readers for the new kinds (#28).
- The legal content must be re-checked when laws change; the date is shown on every screen.
- Network entries can only be changed by whoever added them (Scala's rule); lenders answer borrow
  requests with `reply` items instead of editing the request.
